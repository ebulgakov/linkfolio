# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is pnpm (see `pnpm-lock.yaml` / `pnpm-workspace.yaml`).

- `pnpm install` — install dependencies (also runs `postinstall` → `nuxt prepare`)
- `pnpm dev` — start dev server at `http://localhost:3000`
- `pnpm build` — production build
- `pnpm generate` — static site generation
- `pnpm preview` — locally preview the production build
- `pnpm lint` / `pnpm lint:fix` — ESLint
- `pnpm format` / `pnpm format:fix` — Prettier
- `pnpm type-check` — `nuxt typecheck`
- `pnpm test` — run the Vitest suite (`vitest run`)
- `pnpm storybook` / `pnpm build-storybook` — component workshop for the `.stories.ts` files colocated under `app/shared/ui/**`
- `prepare: "husky"` (via `package.json`) wires a pre-commit hook (`.husky/pre-commit`) that runs `pnpm exec lint-staged` (ESLint `--fix` + Prettier `--write` on staged `.{js,mjs,cjs,ts,vue,json,md,css}`) then `pnpm run type-check` — installed automatically by `pnpm install`, no separate setup step

## Testing

- Vitest, configured for Nuxt via `@nuxt/test-utils` (`vitest.config.ts`: `environment: "nuxt"`). The `@nuxt/test-utils/module` is registered in `nuxt.config.ts`'s `modules` array — required for `mockNuxtImport` to resolve Nuxt auto-imports (e.g. `useRoute`, `navigateTo`) inside tests.
- Two colocation patterns, by side: frontend tests sit at `model/__tests__/use-x.test.ts` next to the composable they cover (e.g. `app/features/collection-form/model/__tests__/use-collection-form.test.ts`, `app/features/shared-collection/model/__tests__/use-collection-unlock.test.ts`); server-side tests sit at `__tests__/` next to the route/util they cover instead (e.g. `server/utils/__tests__/link-fetch-guard.test.ts`, `server/api/upload/__tests__/image.post.test.ts`) — this is why `nuxt.config.ts`'s `nitro.ignore` excludes `**/__tests__/**` (see Architecture).
- Mock at the boundary, not internals: `authClient` via `vi.mock("~/shared/api/auth-client", ...)`; Nuxt auto-imports via `mockNuxtImport` with `vi.hoisted` mutable state boxes (the macro compiles to one hoisted `vi.mock` per import, so behavior varies per test by mutating the box, not by re-registering the mock). Never hit the real better-auth/Neon Auth endpoint from a unit test. Shared boundary mocks for the frontend side live in `app/shared/testing/` (see Architecture) — reuse them rather than re-declaring `vi.mock`/`mockNuxtImport` inline.
- The qa-specialist subagent owns writing/maintaining these tests — see `.claude/agents/qa-specialist.md` for conventions, the current mock catalog, and priority targets (source of truth for what's covered; not duplicated here since it changes with every feature).

## Architecture

Linkfolio is a Nuxt 4 application, organized with **Feature-Sliced Design** (FSD) under `app/`.

- `app/app.vue` — root component, renders `AppHeader` + `NuxtPage` + `AppFooter` (Nuxt 4 source directory convention: app code lives under `app/`, not the project root)
- `nuxt.config.ts` — Nuxt config; the `vuetify-nuxt-module` module is registered here, which auto-imports Vuetify components (e.g. `<v-btn>`, `<v-text-field>`, `<v-card>`) with no manual import needed
- UI library: **Vuetify** via `vuetify-nuxt-module` (icons: MDI webfont, `@mdi/font`)
- Other registered `nuxt.config.ts` modules: `@nuxt/eslint`, `@nuxt/test-utils/module` (see Testing), `@sentry/nuxt/module` (org `home-nbh`/project `linkfolio`, uploads then deletes build sourcemaps), `@nuxt/image` (Cloudinary provider `baseURL`), `@nuxtjs/i18n` (`en`/`ru` locales, `no_prefix` strategy, `detectBrowserLanguage: false`), `nuxt-mcp-dev`. Also: `nitro.ignore: ["**/__tests__/**"]` — Nitro's route scanner globs every `.ts` under `server/api/**` with no test-file exclusion, so colocated `__tests__` there would otherwise get bundled as route handlers and break the server build; `sourcemap.client: "hidden"`.

### File naming

All files under `app/` use kebab-case — lowercase words separated by hyphens, no uppercase letters in the file name. This applies to every file type, including Vue components and composables: `ui/login-form.vue`, `model/use-login-form.ts`, `ui/app-header.vue`. The exported identifier/component name inside the file stays normal JS/Vue convention (PascalCase for components — `LoginForm`, `AppHeader` — camelCase for composables — `useLoginForm`) — only the on-disk file name is constrained to kebab-case.

### FSD layers in use

- `app/pages/` — route pages, thin — compose a feature's exported component. Grew from the original `index.vue`/`login.vue`/`signup.vue` to also cover full collections CRUD via Nuxt's file-based nested/dynamic routing (`collections/index.vue`, `collections/[id]/index.vue`, `collections/[id]/edit.vue`, `collections/[id]/links/new.vue`, `collections/[id]/links/[linkId]/edit.vue`, `new-collection.vue`), the public share view (`shared/[slug].vue`), a discovery page (`published-collections.vue`), and the rest of the auth flow (`forgot-password.vue`, `reset-password.vue`)
- `app/ui/app-header.vue`, `app/ui/app-footer.vue` — app-wide layout, used only from `app.vue`, living in the app layer's own `ui` segment (not a `widgets` slice) as flat files, no local children. `app-header.vue` composes `AppLogoWordmark` (from `~/shared/ui`, see below) + `AuthButtons` (feature) + `NavMenu` (feature, `app/features/nav-menu`); `app-footer.vue` composes `CopyrightNotice` (feature) + `LocaleSwitcher` (feature). `app.vue` imports these two files directly — no `index.ts` barrel, since the app layer isn't a slice and `app.vue` is the only consumer. These previously lived under `app/widgets/`, justified there as composing "multiple independent flows," but each only ever composed one feature — that's the litmus test for `widgets` (see `.claude/skills/feature-sliced-design/references/layer-structure.md`) vs. plain app-layer UI, and they didn't clear it. `app/widgets/` has been removed since nothing qualifies for it now; recreate it if a future case genuinely needs to compose multiple independent feature flows together
- `app/features/` — 16 slices, all following the same shape: a public API from `index.ts` (`export { default as XForm } from './ui/x-form.vue'` + a `useXForm` composable from `model/`), `model/use-x.ts` holding state/logic and result handling, `ui/x.vue` staying presentational only. `login/`, `signup/`, `locale-switcher/`, `auth-buttons/` are the original four; newer slices follow the same pattern — `collection-form/`/`link-form/` (create/edit forms, paired with the `app-input`/`image-upload-field` shared UI below), `shared-collection/` (the password-gated public unlock flow), `nav-menu/` (the header's account/nav menu), plus `collections/`, `collection-links/`, `collection-share-link/`, `published-collections/`, `home-landing/`, `forgot-password/`, `reset-password/`
- `app/features/copyright/` — same shape as the above, despite being single-use: `model/use-copyright.ts` computes the current year + resolves the i18n string (`useCopyright`), `ui/copyright-notice.vue` only renders it. The `.vue` file can't be named `copyright.vue` — `vue/multi-word-component-names` rejects single-word component names — so it's `copyright-notice.vue` exporting `CopyrightNotice`, mirroring how `login`/`signup` slices export `LoginForm`/`SignupForm` rather than `Login`/`Signup`
- `app/shared/api/` — `auth-client.ts` (client-side singleton `authClient` from `better-auth/vue`) and `use-auth.ts` (`useAuth()` factory building a **request-scoped** client with `baseURL` + forwarded cookies, needed for SSR contexts like route middleware — see `app/middleware/guest.ts`/`auth.ts`). Grew a matching pair of request-function modules + composables per domain: `collections.ts`/`use-collection.ts`, `links.ts`, `shared-collections.ts`/`use-shared-collection.ts`, `uploads.ts`, plus `use-published-collections.ts` and `use-session.ts` (`useAuthSession` — distinct from `use-auth.ts`'s `useAuth()`). All re-exported via `app/shared/api/index.ts`
- `app/shared/lib/` — framework-agnostic helpers re-exported via `index.ts`: `validators.ts` (Vuetify `:rules` functions), `use-clipboard.ts`, `use-image-upload.ts`
- `app/shared/ui/` — reusable presentational components re-exported via `index.ts`: `app-alert.vue`, `app-input.vue`, `auth-card.vue`, `collection-card.vue`, `image-upload-field.vue`, plus a `logo/` subdirectory (`app-logo.vue`, `app-wordmark.vue`, `app-logo-wordmark.vue` composing the two). These are the UI-kit pieces to reach for before writing a bespoke Vuetify wrapper. Most have a colocated `.stories.ts` — see Commands for Storybook
- `app/shared/testing/` — colocated test-boundary mocks, not app code: `mocks/` has one `vi.hoisted` mock module per boundary (`auth-client.ts`, `use-auth.ts`, `use-session.ts`, `collections-api.ts`, `links-api.ts`, `shared-collections-api.ts`, `uploads-api.ts`, `route.ts`, `navigate.ts`, `use-state.ts`, `i18n.ts`) plus `deferred.ts` (a `deferred<T>()` helper for controlling when a mocked async call settles). Full conventions for these live in `.claude/agents/qa-specialist.md`, not here — always import from here rather than re-declaring `vi.mock`/`mockNuxtImport` inline in a new test
- `app/middleware/guest.ts` — redirects an authenticated user away from `/login`/`/signup` to `/`; SSR-safe since it uses `useAuth()` rather than the module-level `authClient`. `app/middleware/auth.ts` is the inverse: redirects an unauthenticated user to `/login?redirect=<fullPath>` to protect a route (e.g. `/collections`) — same `useAuth()`/SSR-safety story, and the query param it sets is exactly what `sanitizeRedirect` (below) exists to consume safely
- `app/plugins/i18n-locale.ts` — Nuxt plugin wiring i18n locale resolution at app init

### Auth conventions (Better Auth via `better-auth/vue`)

- Neon Auth is Better Auth-based; there's no official Vue/Nuxt package, so this app talks to it directly through `better-auth/vue`'s client (not `@neondatabase/auth`, which only ships React/Next.js/vanilla-JS entry points)
- Two client instances exist deliberately: the singleton `authClient` (shared/api/auth-client.ts) for client-side reactive session state, and `useAuth()` (shared/api/use-auth.ts) whenever code must also run on the server (middleware, SSR data fetching) — pick based on whether the call site executes during SSR
- When reading the session in a component that renders during SSR, pin `authClient.useSession`'s `useFetch` key explicitly (see `app/features/auth-buttons/model/use-auth-buttons.ts`) to avoid a client/server key mismatch and hydration warning
- `use-auth-buttons.ts` awaits `authClient.useSession(...)` inside the composable itself (not inside the `.vue` file), so any other composable call that must resolve against the Nuxt instance (`useRouter()`, etc.) has to happen _before_ that `await`, not after — Vue's `<script setup>` compiler auto-restores the instance context around a top-level `await` via `withAsyncContext`, but that transform only applies inside an SFC's `<script setup>` block, not inside a plain `.ts` composable function. A call placed after the `await` there throws "called outside of a plugin/setup" once the logic is extracted out of the `.vue` file
- Any redirect target taken from a query param (e.g. `?redirect=`) must be sanitized to a same-origin path before use — see `sanitizeRedirect` in `use-login-form.ts` (exported for direct unit testing) — to avoid an open-redirect vector
- Database: **Neon serverless Postgres** (`@neondatabase/serverless`), project "Linkfolio". `.neon` holds the linked `orgId`/`projectId`; run `npx neon env pull` after switching branches/projects to refresh `.env` (gitignored) with `DATABASE_URL` (pooled), `DATABASE_URL_UNPOOLED` (direct), `NEON_BRANCH`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_JWKS_URL` — never expose these to client-side code.
  - ORM: **Drizzle** (`drizzle-orm`/`drizzle-kit`, configured in `drizzle.config.ts`). Schema lives in `server/db/schema.ts`; migrations are generated/applied via `pnpm db:generate` / `pnpm db:migrate` (wrapping `drizzle-kit generate`/`migrate`) into `server/db/migrations/`. `server/db/index.ts` is the pooled client (`DATABASE_URL`) used for application queries; `drizzle.config.ts` uses `DATABASE_URL_UNPOOLED` for migrations and restricts `schemaFilter: ["public"]`. `server/db/neon-auth.ts` holds a reference-only Drizzle table declaration for Neon Auth's `neon_auth.user` table (FK typing only) — deliberately excluded from `schema.ts` so drizzle-kit doesn't try to manage Neon Auth's own schema.

### Server (Nitro API + DB)

- `server/db/schema.ts` defines three tables. `collections` — one per user's link collection, globally unique `slug` (checked via an AJAX endpoint before submit), a case-insensitive per-user unique index on `name`, `published`/`shared` visibility flags, and an optional plaintext `password` column — stored unhashed *deliberately*, because the owner's edit form redisplays the current password as an unmasked text field, which a one-way hash would make impossible; `NULL` means no password, normalized from `""` at the zod-validation boundary in the collections POST/PATCH routes (see the inline comment on that column before touching it). `urls` — a per-user cache of normalized URLs (lowercased scheme+host, no trailing slash, tracking params stripped), holding `title`/`description`/`imageUrl`/`fetchStatus` populated asynchronously by link-preview scraping. `collection_items` — the join table between the two, with a manual `position` column for ordering (no drag-and-drop-library-owned order field) and a unique `(collectionId, urlId)` constraint. Cross-user ownership on inserts (`urls.userId` must match the target collection's owner) is enforced in the service layer, not structurally — see the schema file's closing comment.
- `server/api/` is a Nitro file-based REST surface: `auth/[...all].ts` (Better Auth catch-all), full `collections` CRUD (`index.get/post`, `[id].get/patch/delete`, `check-slug.get`) plus nested `collections/[id]/links` CRUD, `links/preview.post.ts` (server-side link-metadata scraping), public/password-gated read access under `shared/` (`index.get.ts`, `[slug].get.ts`, `[slug]/links/index.get.ts`, `[slug]/unlock.post.ts`), and `upload/image.post.ts`/`image.delete.ts` for Cloudinary uploads.
- `server/utils/` holds Nitro auto-imported, server-only helpers — e.g. `collection-errors.ts`/`link-errors.ts` (`createError` builders), `url-normalize.ts`, `link-fetch-guard.ts`, `shared-collection-password.ts` (gates guest access against the `collections.password` column above).

## Worktree policy

Never use `EnterWorktree` in this repo — always work directly in the current branch/checkout. This is enforced by a `PreToolUse` hook (`.claude/hooks/block-worktree.sh`, wired up in `.claude/settings.json`) that denies every `EnterWorktree` call: if it detects only the main checkout (`git worktree list --porcelain`), it explains the policy; if it detects an extra worktree, it warns that a previous agent session may still have work in progress there and to close/merge that first. `settings.json` also sets `worktree.bgIsolation: "none"` so background sessions can still edit files directly without ever needing `EnterWorktree` to unlock that (`worktree.bgIsolation` requires Claude Code 2.1.143+; on older clients this setting is ignored and background sessions still require a worktree).
